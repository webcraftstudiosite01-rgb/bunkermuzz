# Правила для AI-ассистентов (AI Rules)

Данный документ содержит строгие правила для всех языковых моделей (LLM) и автономных агентов, взаимодействующих с репозиторием **BunkerMuzz**.

---

## 1. Сохранение существующей архитектуры

1. **Размещение файлов:**
   - Код Django (проекты, приложения, `manage.py`) строго внутри `projects/`.
   - Глобальные шаблоны — внутри `templates/`.
   - Статические файлы (CSS, JS, картинки) — внутри `assets/`.
   - Документация, правила и чек-листы — внутри `instructions/`.
2. **Не ломать пути:**
   - Путь к корню проекта в `settings.py` вычисляется через `BASE_DIR.parent` (`ROOT_DIR`). Не переопределяйте пути жесткими строками.
3. **Согласованность:**
   - При добавлении нового приложения в `projects/` всегда регистрируйте его в `INSTALLED_APPS` файла `projects/config/settings.py` и подключайте его `urls.py` в `projects/config/urls.py`.

---

## 2. Безопасность и чистота кода

1. **Никаких секретов в коде:**
   - Не добавляйте реальные токены, пароли и приватные ключи в коммиты или исходный код.
   - Используйте переменные окружения и `os.getenv()`.
2. **Валидация перед завершением задачи:**
   - Перед отправкой ответа пользователю обязательно запускать проверку целостности Django:
     ```bash
     python projects/manage.py check
     ```
   - Запускать тесты:
     ```bash
     python projects/manage.py test
     ```
3. **Чистые миграции:**
   - При изменении моделей создавать и применять миграции:
     ```bash
     python projects/manage.py makemigrations
     python projects/manage.py migrate
     ```

---

## 3. Требования к оформлению ответов

- Всегда предоставлять краткий, структурированный отчет о проделанной работе.
- Указывать относительные или кликабельные пути к созданным/измененным файлам.
- При создании новых фич обязательно обновлять соответствующие документы в `instructions/`.
